# 三级库状态名称重构

## 背景

当前「未使用 / 已使用」是按每一支药品单独判断的，导致同一张卡片里既有已用的也有未用的时，卡片会被拆开分别落到两个 tab 里，语义含糊。卡片自身的状态则是「全部用完才算已使用」，两套口径不一致。

## 新的状态口径（以卡片为单位）

统一按“这张卡里还有没有可用的药”来判断，三种状态：

| 状态 | 含义 | 视觉 |
| --- | --- | --- |
| 未使用 | 一支都没用（n = 0） | 品牌绿边框 + 绿色图标 |
| 使用中 | 用了一部分（0 < n < m），文案「已用 n/m」 | 橙/黄边框 + 同色图标 |
| 已用完 | 全部用完（n = m） | 浅灰边框 + 灰色图标，明细文字保持删除线与浅色 |

单支药品卡（m = 1）与只治疗 1 头牛的组合卡不会出现「使用中」，只在「未使用」和「已用完」之间切换，不显示分数。

组合药品卡采用完全相同的规则，把「支」换成「头牛的用药次数」。

## 顶部筛选 tab

由三项变为四项，计数改为按卡片（分组）统计，而不是按单支药品：

`全部 N` ｜ `未使用 N` ｜ `使用中 N` ｜ `已用完 N`

一张卡只会出现在一个 tab 里，不再被拆开。

## 排序

未使用 → 使用中 → 已用完；同组内未使用的按领取时间，已用完的按使用时间。

## 技术细节

- 文件：`src/routes/m.level3.tsx`
- 先按 `comboId` / `药品+规格+领用人` 完成分组，再对分组计算 `usedCount / total` 得出卡片状态；tab 过滤与计数都基于分组结果，而不是当前的逐条 `i.used` 过滤。
- `ItemCard` 与 `ComboCard` 共用一个 `groupStatus(usedCount, total)` 辅助函数，返回状态 key、文案、边框色与图标色，替换现在两处各自写死的 `allUsed ? ... : ...` 判断。
- 「使用中」新增一个中间色（沿用组合卡已有的橙色 `#E5751A` 体系作为进行中色），未使用维持品牌绿，已用完维持 `#E8EAE9`。
