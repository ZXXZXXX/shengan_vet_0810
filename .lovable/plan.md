
为疾病治疗类工单引入"复查任务"闭环，并打通"继续观察 → 复诊上报 / 到期自动确认治愈"的全流程。这是一次较大的流程改造，建议先确认范围后再落地。

## 一、复查任务（兽医验收）

适用范围：所有 `kind === "疾病治疗"` 的工单，在最后一个药物处方执行任务被记录为已完成后，**自动追加一个"复查"子任务**，仅 `vet` 角色可执行（非兽医进入显示"待兽医复查"占位）。

复查页面（新路由 `m.health.$id_.review.tsx`）核心三选一：

```text
┌─ 复查结论 ──────────────────────────────┐
│  ○ 治愈    ○ 放弃    ○ 继续观察          │
└────────────────────────────────────────┘
```

- **治愈**：是否转栏（开关）→ 选择转栏去向（牛舍选择器）→ 提交 → 工单 `status = "已完成"`。
- **放弃**：放弃原因（预设标签 + 其他）→ 是否转栏 / 去向 → 提交 → 工单 `status = "已终止"`。
- **继续观察**：观察天数（数字输入，默认 3 天）→ 是否转栏 / 去向 → 提交 → 工单仍为 `status = "执行中"`，但不再有可执行任务，详情页显示"观察中 · 剩余 X 天"。

## 二、继续观察期间的复诊上报

三个入口都能发起复诊，全部最终落到 `m.report.tsx`：

1. **健康上报页 (`m.report.tsx`)**：顶部增加"是否复诊"开关，若是 → 弹出"关联工单"选择器（只列出当前耳号下 `status === "观察中"` 的疾病工单）。
2. **扫码上报 (`m.scan.tsx`)**：扫到耳号后，若该牛存在观察中工单，弹窗询问"是否为复诊？"，是则跳转 `m.report?revisitFrom=WO-xxxx&lock=1`。
3. **工单详情页"健康上报"按钮**：仅在 `status === "观察中"` 时显示，点击直接 `navigate({ to: "/m/report", search: { revisitFrom: id, lock: 1 } })`，默认即为复诊且锁定关联。

复诊上报提交后：
- 新工单自动同步旧工单的耳号 / 牛舍 / 既往诊断 / 用药历史。
- 旧工单 `status` 保持 `观察中`，详情页"复诊记录"区块新增一条链接到新工单。

## 三、观察到期自动确认治愈

`reviewedAt + observeDays` 到期后，若期间没有任何复诊上报：
- 系统生成一个"确认治愈"任务挂在该工单下，仅助理可执行。
- 在 `m.notifications.tsx` 推一条消息："工单 WO-XXXX 观察期满，请确认治愈"。
- 助理打开任务 → 是否转栏 / 去向 → 提交 → 工单 `status = "已完成"`。

由于当前是纯前端 mock 数据，**到期判断**用 `Date.now() >= reviewedAt + observeDays * 86400_000` 在列表/详情进入时即时计算，无需真正的定时任务。
